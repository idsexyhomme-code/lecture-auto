#5 자동화 파이프라인 연결하기lecture_script

코스: claude-customer-support · 에이전트: producer

HOOK (45초)

문의가 들어왔는데 또 자리를 비웠습니다. 카카오채널 알림은 쌓여 있고, 이메일 받은편지함도 밀려 있죠. 손으로 하나하나 답장 쓰다 보면 반나절이 사라집니다. 오늘 이 흐름을 완전히 끊어드리겠습니다. 이 영상 하나로, 문의가 들어오는 순간 Claude가 초안을 만들어 회원님 앞에 갖다 놓는 파이프라인을 직접 작동시켜 봅니다.

PROMISE (30초)

이번 차시가 끝나면, Make 또는 Zapier 시나리오를 설정해서 이메일·카카오채널 문의 수신부터 Claude 자동 초안 생성, 그리고 본인에게 전달까지 이어지는 전체 흐름을 실제로 돌릴 수 있게 됩니다.

CORE (8–10분)

중요 개념 1 — 트리거-액션 구조: "도미노 3개"

설명 자동화 파이프라인은 도미노 3개짜리 구조입니다. 첫 번째 도미노가 '트리거', 수신 채널입니다. 두 번째가 'Claude API 호출', 중요한 처리입니다. 세 번째가 '액션', 초안 전달입니다. 이 순서가 흔들리면 파이프라인 전체가 무너집니다.

예시 카카오채널로 "환불 가능한가요?" 문의가 도착합니다. Make가 이걸 감지해 트리거를 발동합니다. Claude에게 문의 내용을 넘겨 초안을 받아옵니다. 그 초안이 운영자 이메일로 날아옵니다. 총 세 단계, 30초 이내에 끝납니다.

반례 트리거 없이 Claude를 직접 실행하면 자동화가 아닙니다. 매번 사람이 복붙해야 하는 반자동일 뿐입니다. 도미노 첫 번째가 없으면 나머지도 의미가 없습니다.

정리 수신 채널 → Claude API → 발송, 이 3단 도미노를 머릿속에 박아 두세요. Make나 Zapier는 이 도미노를 연결하는 레일입니다.

중요 개념 2 — API 키 발급 및 보안 처리: "열쇠는 금고 안에"

설명 Claude API를 쓰려면 Anthropic 콘솔에서 API 키를 발급받아야 합니다. 이 키는 계정 비밀번호보다 더 민감합니다. 시나리오 화면에 그대로 붙여 넣으면 노출 위험이 생깁니다. Make와 Zapier 모두 '커넥션' 또는 '환경변수' 기능을 제공합니다. 키는 반드시 그 안에 저장하세요.

예시 Make 기준으로 설명합니다. 좌측 메뉴 'Connections' → 'Add connection' 클릭. 서비스는 'HTTP' 선택, 헤더에 x-api-key 값을 입력합니다. 이후 시나리오 어디서든 이 커넥션만 참조하면 됩니다. 키 값이 화면에 노출되지 않습니다.

반례 시나리오 노트나 텍스트 모듈에 키를 직접 적어 두는 경우가 있습니다. 시나리오를 공유하거나 복제하는 순간 키가 같이 넘어갑니다. 제 경험상 이 실수로 키를 재발급한 경우를 꽤 봤습니다.

정리 "열쇠는 금고 안에"를 기억하세요. API 키 = 열쇠, 커넥션 설정 = 금고입니다. 열쇠를 문 앞에 두지 마세요.

중요 개념 3 — 인간 검토 게이트: "신호등 설계"

설명 자동화에는 두 가지 모드가 있습니다. 초안을 운영자가 확인 후 보내는 '승인 모드', 빨간불입니다. Claude 초안을 바로 발송하는 '자동 발송 모드', 초록불입니다. 대부분의 경우 초기에는 승인 모드가 안전합니다.

예시 승인 모드 설계입니다. Claude가 초안을 생성하면 운영자 이메일로 먼저 보냅니다. 이메일 본문에 "승인 링크"를 만들어 클릭 시 고객에게 발송됩니다. Make의 'Webhook' 모듈로 이 흐름을 구현할 수 있습니다. 확인 없이 나가는 답장은 없습니다.

반례 자동 발송 모드도 나쁜 건 아닙니다. 단, 프롬프트가 충분히 검증된 이후에 적용하세요. 검증 전에 자동 발송하면 엉뚱한 초안이 고객에게 나갑니다. 신호등이 항상 초록일 수는 없습니다.

정리 신호등 설계, 기억하세요. 처음엔 빨간불(승인 모드)로 시작합니다. 파이프라인이 안정되면 초록불(자동 발송)로 바꿉니다. 이 판단은 데이터가 쌓인 뒤에 하세요.

EXERCISE (3–4분)

지금 영상을 일시정지하고 아래 단계를 직접 따라 하세요. 완료하면 스크린샷 2장이 나옵니다.

Step 1 — Make 시나리오 뼈대 만들기 (1분) Make 접속 후 새 시나리오를 생성합니다. 첫 번째 모듈: 'Email' 또는 'Gmail' → 'Watch Emails' 선택. 두 번째 모듈: 'HTTP' → 'Make a request' 선택. 세 번째 모듈: 'Email' → 'Send an Email' 선택. 이 3개 모듈을 캔버스에 배치하세요.

Step 2 — Claude API 연결 (1분) 두 번째 모듈(HTTP) 설정 화면을 엽니다. URL: https://api.anthropic.com/v1/messages Method: POST Headers에 x-api-key와 anthropic-version 추가. Body에는 아래 JSON 구조를 붙여 넣으세요.

{
  "model": "claude-3-5-sonnet-20241022",
  "max_tokens": 512,
  "messages": [{"role": "user", "content": "{{이메일 본문}}"}]
}

{{이메일 본문}}은 Make의 첫 번째 모듈 출력값으로 매핑하세요.

Step 3 — 테스트 실행 (1분) 시나리오 하단 'Run once' 클릭. 본인 이메일로 테스트 문의 하나를 발송합니다. Make가 감지하면 각 모듈에 초록 체크가 붙습니다. 세 번째 모듈까지 체크가 붙으면 성공입니다.

Step 4 — 결과물 저장 (30초) 작동 완료된 시나리오 화면 스크린샷 1장. 수신된 자동 초안 이메일 화면 스크린샷 1장. 이 두 장이 이번 차시 실습 결과물입니다.

CTA (30초)

다음 차시 #6에서는 RAG를 파이프라인에 붙입니다. 내 FAQ 문서를 Claude가 직접 참조해서 답변하는 흐름입니다. 지금 실습 결과물 스크린샷을 댓글에 남겨 주세요. 잘 안 되는 부분이 있으면 어느 단계인지 같이 적어 주시면 피드백 드리겠습니다.
