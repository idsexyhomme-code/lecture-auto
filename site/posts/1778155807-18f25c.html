#13 Claude 쓰는 방법 오류 진단 및 개선하기lecture_script

코스: claude-autowork · 에이전트: producer

HOOK (45초)

Claude한테 보고서 맡겼더니 엉뚱한 수치가 들어왔거나, 어조가 갑자기 반말 같아진 경험 있으시죠?

열심히 프롬프트 짰는데 결과물을 믿을 수가 없으면, 자동화가 아니라 오히려 검수 부담이 두 배가 됩니다.

오늘 이 문제를 끝냅니다.

Claude 출력에서 반복적으로 생기는 오류에는 패턴이 있습니다. 패턴을 알면 진단이 빠르고, 진단이 빠르면 수정 프롬프트 하나로 해결됩니다.

PROMISE (30초)

이 차시가 끝나면, Claude 출력에서 발생하는 4가지 오류 유형을 10초 안에 분류하고, 유형별 수정 프롬프트를 즉시 작성할 수 있게 됩니다.

CORE (8–10분)

중요 개념 1 — 오류 유형 분류: '4칸 진단 박스'

설명

Claude 출력 오류는 크게 네 가지로 나뉩니다.

  • 사실 오류: 수치·날짜·고유명사가 틀림
  • 형식 불일치: 요청한 구조와 출력 구조가 다름
  • 어조 이탈: 요청한 톤과 실제 문체가 어긋남
  • 누락: 요청한 항목이 출력에 빠져 있음

이 네 칸을 머릿속에 2×2 박스로 그려두세요. 가로축은 '내용 vs. 형태', 세로축은 '있는 것이 틀림 vs. 있어야 할 것이 없음'입니다.

예시

월간 매출 보고서를 요청했을 때를 봅시다.

  • "3분기 매출이 12억"이라고 썼는데 실제는 9억 → 사실 오류
  • 표로 달라고 했는데 문단으로 옴 → 형식 불일치
  • 공식 보고서인데 "엄청 좋은 성과네요"가 들어감 → 어조 이탈
  • 전월 대비 증감률 항목이 아예 없음 → 누락

반례

"문장이 어색하다"는 이 네 칸 중 어디에도 속하지 않습니다. 그건 '표현 품질'로 별도 기준이 필요합니다. 오늘 다루는 4가지 유형과 혼동하지 마세요.

정리

오류를 발견하면 먼저 4칸 박스에 배치하세요. 유형이 정해져야 수정 방향이 정해집니다.

중요 개념 2 — 품질 검수 체크리스트: '신호등 3단계'

설명

출력물이 나왔을 때 무작정 읽지 말고, 신호등처럼 3단계로 검수하세요.

  • 빨강 (즉시 차단): 사실 오류·누락 → 사용 전에 반드시 수정
  • 노랑 (조건부 통과): 어조 이탈 → 수신자·용도에 따라 수정 여부 결정
  • 초록 (통과): 형식 불일치 중 사소한 것 → 수작업 편집으로 빠르게 처리

이 3단계를 거치면 "전부 다 고쳐야 하나?"라는 막막함이 없어집니다.

예시

거래처 제안서를 Claude로 작성했습니다. 경쟁사 이름이 잘못 들어갔으면 빨강입니다. 소제목이 볼드 처리 안 됐으면 초록입니다. 문체가 약간 캐주얼하면 수신자가 친밀한 파트너라면 노랑에서 통과시킬 수 있습니다.

반례

모든 오류를 빨강으로 처리하면 검수 시간이 자동화 이전보다 늘어납니다. 제 경험상 초록 항목은 10초 편집으로 해결되는 경우가 대부분입니다.

정리

신호등 3단계로 우선순위를 정하면, 검수 시간이 절반 이하로 줄어드는 경우가 많습니다.

중요 개념 3 — 프롬프트 디버깅: '오류 역추적 3문장 공식'

설명

오류 유형을 알았으면 수정 프롬프트를 써야 합니다. 이때 쓸 수 있는 공식이 있습니다.

[오류 지목] + [올바른 기준 명시] + [재출력 요청]

3문장으로 구성됩니다. 길게 쓸 필요 없습니다.

예시

유형별로 각각 한 번씩 보겠습니다.

  • 사실 오류 수정 프롬프트: "위 출력에서 3분기 매출을 '12억'으로 기재했는데, 실제 수치는 '9억'입니다. 해당 수치를 정정하고 관련 문장을 다시 작성해 주세요."
  • 형식 불일치 수정 프롬프트: "출력이 문단 형식으로 왔는데, 요청한 형식은 3열 표입니다. 같은 내용을 표로 다시 정리해 주세요."
  • 어조 이탈 수정 프롬프트: "전체 문체가 구어체로 쓰였습니다. 외부 보고용 격식체로 전체를 다시 작성해 주세요."
  • 누락 수정 프롬프트: "전월 대비 증감률 항목이 빠져 있습니다. 각 항목 하단에 증감률을 추가해 주세요."

반례

"다시 써줘"처럼 오류를 지목하지 않으면, Claude는 같은 오류를 반복하는 경우가 대부분입니다. 원인을 짚어야 수정이 됩니다.

정리

3문장 공식은 오류 지목·기준 명시·재출력 요청 순서를 지킬 때 가장 효과가 좋습니다.

EXERCISE (3–4분)

지금부터 영상을 일시정지하고 직접 만들어 보세요.

준비물: 메모장, 혹은 Claude 대화창

Step 1 — 진단 체크리스트 만들기 (1분)

아래 4줄을 그대로 복사해서 메모장에 붙여넣으세요.

□ 사실 오류: 수치·날짜·고유명사가 맞는가?
□ 형식 불일치: 요청한 구조로 출력됐는가?
□ 어조 이탈: 요청한 톤과 문체가 일치하는가?
□ 누락: 요청한 항목이 모두 포함됐는가?

이게 회원님의 기본 검수 체크리스트입니다.

Step 2 — 오류 유형 분류 연습 (1분)

다음 상황을 읽고 4칸 박스 중 어디에 해당하는지 적으세요.

  • Claude가 이메일을 작성했는데, 수신자 이름이 '김철수'인데 '박철수'라고 나옴 → ( )
  • bullet list로 달라고 했는데 번호 목록으로 나옴 → ( )
  • 격식체 요청했는데 "드립니다" 대신 "할게요"가 쓰임 → ( )
  • 결론 섹션이 없음 → ( )

정답은 순서대로 사실 오류·형식 불일치·어조 이탈·누락입니다.

Step 3 — 수정 프롬프트 4종 작성 (2분)

Step 2의 네 가지 상황에 대해, 각각 3문장 공식으로 수정 프롬프트를 직접 작성해 보세요.

[오류 지목] + [올바른 기준 명시] + [재출력 요청]

작성이 끝나면 영상을 다시 재생하세요.

CTA (30초)

다음 차시 #14에서는 Claude 방법를 팀 단위로 확장하는 법을 다룹니다. 혼자 쓰던 프롬프트를 팀 전체가 일관되게 쓰는 구조를 만드는 내용입니다.

오늘 만든 수정 프롬프트 4종을 실제로 써보셨으면, 어떤 유형의 오류가 가장 자주 나왔는지 댓글에 남겨주세요. 다음 차시 내용 구성에 반영하겠습니다.
